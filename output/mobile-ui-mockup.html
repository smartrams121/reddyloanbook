Items Flagged for Review
Flag 1 — "Collect → Individual Posting Page"
The prompt says: "clicking Collect → go directly to /posting/[customerId]". But the Collect button is in the footer nav bar — it has no customer context. The footer is visible on every page, so there's no way to know which customer to open.

Options:
• Keep Collect going to /posting (the customer selection/search page) — this is the current correct behavior
• Or did the prompt mean: from the Customer detail page, a collect button should go to that customer's posting? That would be a different feature entirely

Recommendation: Skip this item. The current Collect → posting page behavior is correct for a footer nav button.
Flag 2 — "Full Width Mobile Layout" (Item 7)
This item asks to audit and fix every page, card, table, modal, and form in the entire app for mobile overflow. This is a separate sprint-level task, not a single change.

It touches 30+ page files, all table components, all modal components, and all form layouts. Bundling it with these header/footer changes risks breaking things and makes testing very difficult.

Recommendation: Do items 2–6 and 8 first (header/footer/sidebar — all in AppShell.tsx). Then tackle item 7 as a separate pass, page by page, with testing between each.
Flag 3 — Icon size w-7 h-7 vs current w-6 h-6
You previously requested bigger icons and we set them to w-6 h-6. The prompt now asks for w-7 h-7 (28px). That's fine, but wanted to confirm — the header already gets tight with Customers + Loans + business dropdown at phone width. Going bigger may cause the header to clip on smaller phones (375px).

Recommendation: Keep w-6 h-6 in the header (already bigger than before), bump footer icons to w-7 h-7 since footer has more room.
